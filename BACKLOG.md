# Бэклог: отложенное и технический долг

Обновляется по мере прохождения MVP. Формат: что отложено, почему, в каком MVP планируем вернуться. Статус: `[ ]` открыто, `[x]` сделано.

## Отложено из MVP-0

### Полёт и автопилот
- [ ] **Обход препятствий и поиск пути.** Автопилот летит по прямой и может врезаться в планету, мишень или чёрную дыру; клик внутри планеты просто переносится на поверхность. Вернуться: MVP-1 (для ИИ врагов, минимально) и MVP-3 (арены с астероидами).
- [ ] **Баланс маневровых двигателей.** Мощности заданы условно: тормозные 50% и боковые 25% от маршевых. Вернуться: балансировка в MVP-1 и MVP-4.
- [ ] **Вращающие моменты не привязаны к модулям.** Рулевой момент берётся абстрактным бюджетом от маршевых двигателей, а не от сопел. Разрушение сопел не влияет на скорость разворота. Вернуться: MVP-2 (когда появятся посты и энергосистема).
- [ ] **Разворот медленных кораблей.** У крейсера угловое ускорение мало, возможны перерегулирования при коротких перелётах. Нужен более осторожный профиль поворота. Вернуться: по результатам игровых тестов.
- [ ] **Пилот и flight assist.** Качество автопилота ещё не зависит от уровня пилота и экипажа. Вернуться: MVP-2.

### Физика и разрушение
- [ ] **Баланс урона.** Коэффициенты кратеров, `COLLISION.damagePerEnergy`, HP материалов подобраны на глаз. Вернуться: MVP-1.
- [ ] **Столкновения без трения между кораблями и без CCD.** Скорость ограничена 500 кл/с, быстрые снаряды MVP-1 потребуют сегментного теста. Вернуться: MVP-1 (снаряды делаем отдельным raycast-ом).
- [ ] **Упрощения при разрыве корпуса:** угловой момент при потере массы сохраняется приближённо, отброс обломков задан константами. Вернуться: по необходимости.
- [ ] **Отсеки и давление** (клеточная модель воздуха) не начаты. Вернуться: MVP-2.
- [ ] **Разрушение обломков в пыль:** порог `DUST_MIN_COLUMNS = 3` жёсткий, лут из обломков не реализован. Вернуться: MVP-3.

### Рендер и производительность
- [ ] **Полная перерисовка текстуры корабля** при любом изменении (без dirty-rect). При тысячах попаданий в секунду (лучи MVP-1) может понадобиться. Вернуться: MVP-1 по замерам.
- [ ] **Вращение пикселей без «снапа»:** при повороте текстура с nearest-фильтром мерцает. Вернуться: MVP-6 (полировка).
- [ ] **FPS на реальном железе** мерили только через HUD в браузере Claude; нет замеров на слабых устройствах и мобильных. Вернуться: MVP-6.
- [ ] **Эффекты света** (bloom, свечение лазеров) пока только аддитивные частицы. Вернуться: MVP-6.
- [ ] Нет звука. Вернуться: MVP-6.

### Интерфейс
- [ ] **Строго «только мышь».** Сейчас есть отладочные клавиши (Space пауза, R сброс) и панель разработчика. Вернуться: MVP-4 (игровой интерфейс).
- [ ] **Мини-карта и быстрый переход к телам арены** (планета, луна, звезда, чёрная дыра) — предлагали, не делали. Вернуться: по запросу.
- [ ] Нет адаптации под тач и маленькие окна. Вернуться: MVP-4.

### Инфраструктура
- [ ] Нет README, CI, ESLint/Prettier. Удалённый репозиторий не подключён (вы пушите сами).
- [ ] Нет браузерных e2e-тестов: интерфейс проверяется вручную, симуляция — Vitest.
- [ ] Версии инструментов очень свежие (TypeScript 7, Vite 8, Vitest 5): при проблемах сборки проверять совместимость.
- [ ] Размер бандла ~290 КБ (gzip ~89 КБ) без code splitting; при росте проекта пересмотреть.

## Отложено из ГДД (на следующие MVP)

| Тема | Где вернёмся |
|---|---|
| Двигатели как потребители энергии | MVP-1 решаем: пока энергия только у оружия и щитов; двигатели считаются бесплатными |
| Палубы как игровая механика, отсеки, двери, пожары | MVP-2 |

| Док, редактор, ремонт по таймерам, парк кораблей | MVP-4 |

| Мир, лор, кампания, боссы, платежи | MVP-6 |

## Идеи, не входящие в план
- Прицеливание в конкретную клетку вражеского корабля (в MVP-1 берём как часть управления оружием).
- Фракционная окраска кораблей и декали.
- Замедление времени как ресурс с перезарядкой (сейчас бесплатное).
